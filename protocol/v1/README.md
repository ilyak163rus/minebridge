Общие данные протокола 1.0
=========================

Нормативная база: [контракт r1 и уточнения T03](../../docs/contracts/V0_1_CONTRACT.ru.md).
[fixtures/corpus.json](fixtures/corpus.json) — один корпус для Python и Java;
он не содержит действующих токенов и не является кодом сервера.

Каждый case содержит name, mode, вход и expect. mode: request,
hello-response, blocks-response или stream. expectedId задаёт ожидаемый ID
ответа; null используется для проверки ошибки без определимого ID.

Ровно один вид входа:

- text — исходная JSON-строка; в stream включает разделители LF, в других
  режимах представляет payload без LF;
- hex — байты, включая намеренно неверный UTF-8;
- construction — prefix + repeat * count + suffix. Так границы размера
  не требуют многократного хранения строк по 64 КиБ.

Для stream chunkSizes задаёт размеры последовательных частей, остаток
подаётся последним. eof=true вызывает finish(). Ожидаемые frames проверяются
на уровне framing; JSON в этих кадрах не обязан быть корректным.

expect.kind: request, notification, result, error, failure или frames.
Дополнительные ожидания: id, code, reply, close, frameCount. Ошибка reply=false
не создаёт обязательного RPC-ответа. Флаги описывают codec, а не всю политику
состояния сессии. В корпусе сохраняются исходные 1/1.0/1e0 и повторные ключи;
нельзя сначала читать payload как обычный JSON и затем сериализовать заново.

Потоковый decoder ограничивает незавершённый payload 65536 байт, включая CR
перед LF. При ошибке feed не возвращает кадры из этого вызова и становится
закрытым; finish не выдаёт неполный кадр. Повторное использование после EOF
или ошибки даёт DECODER_CLOSED. Сокеты/таймеры реализованы отдельно в T04.

Java decodeEnvelope проверяет только JSON и оболочку; validateRequestParameters
проверяет параметры команды. Строгий decodeRequest вызывает оба и продолжает
проходить весь корпус. TCP использует decodeEnvelope: будущий router сначала
проверит состояние сессии и доступ, затем параметры. Эти проверки не требуют
переноса авторизации в сетевой поток.

Внутренние деревья обоих кодеков используют JsonNumber с текстом числа;
идентификатор проверенного сообщения доступен как обычный int/Long. Payload,
параметры авторизации и удалённые сообщения ошибок не входят в repr/toString
и диагностику codec. Python-классификация удалённой ошибки использует таблицу
числовых кодов; текст сообщения в локальное исключение не переносится.
