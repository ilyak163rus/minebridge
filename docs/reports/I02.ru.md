Реализованный API
-----------------

```python
mc.setBlock(x, y, z, block, data=0)
mc.setBlocks(x1, y1, z1, x2, y2, z2, block, data=0)
mc.getBlock(x, y, z)                   # старый числовой ID
mc.getBlocks(x1, y1, z1, x2, y2, z2)  # {(x,y,z): старый ID}

mc.blocks.getBlock(x, y, z)           # BlockSpec с полными состояниями
mc.blocks.getBlocks(...)             # {(x,y,z): BlockSpec}

mc.setBlock(x, y, z, block.OAK_STAIRS.withStates(facing="east", half="bottom"))
mc.setBlock(x + 1, y, z, "minecraft:oak_log[axis=x]")
```

Root и mc.blocks установки используют общую реализацию. Buffered остаётся
режимом по умолчанию; flush, чтение и обычный close дожидаются предшествующих
записей. Обе границы области включены, углы допускаются в любом порядке,
дробные координаты округляются вниз. Чтение передаётся страницами по 64 позиции.

setBlocks выполняется частями, не удерживая игровой поток до окончания всей
области. Пока сессия ждёт чанки/строит, её очередь сохраняет FIFO, а другие
подключения продолжают работу. system.progress сообщает о живом задании;
он не заменяет итоговое подтверждение. Для конфликтующей записи в область
чужого строительного задания предусмотрен RegionBusyError.

Чанки загружаются и при необходимости генерируются автоматически, без игрока.
Запросы одной загрузки объединяются, удержание чанков учитывается совместно
для сессий и освобождается при завершении, ошибке и отключении. Уже начатую
генерацию Paper нельзя отменить задним числом; отменённое задание не делает
последующих установок и не приобретает поздние tickets.

Каталог и старые ID
------------------

Снимок настоящего Registry.BLOCK закреплённого Paper 26.2 build 133 содержит
1196 типов блоков. Сгенерированы 1258 статических типизированных имён, включая
совместимые исторические aliases; импорт не подключается к сети.

Таблица legacy содержит 361 проверенную ID/data-пару для 110 старых ID.
Преобразования и полные состояния получены из Paper UnsafeValues.fromLegacy
в отдельном инструменте экспорта; production использует сохранённую таблицу.
Исторические имена сохраняют LegacyBlock с id/data; новые — BlockSpec.
Оба типа поддерживают неизменяемый withStates.

Три коллизии исторических имён с современными ключами сохранены явно:
MINECRAFT_PUMPKIN, MINECRAFT_STONE_SLAB, MINECRAFT_TORCH дают современные
блоки, а старые PUMPKIN/STONE_SLAB/TORCH сохраняют legacy-смысл.

Новые блоки и неоднозначные старые соответствия не получают выдуманных чисел.
Например, современная вода может соответствовать старым 8/9, лава — 10/11,
dead_bush — 31/32. Корневое чтение в таких случаях вызывает
UnsupportedLegacyBlockError; современное чтение возвращает BlockSpec.
355 обратных соответствий проверены точно, шесть строк имеют ожидаемую
неоднозначность. Полной поддержки каждого исторического ID/data не обещаем.

Проверки и фактические результаты
--------------------------------

- 406 Java cases: включая асинхронные чанки, tickets, FIFO, удержания,
  переполнение объёма, резервирование, частичную ошибку и очистку при остановке.
- 134 Python-теста из исходников на Python 3.11 и 3.14. Упаковка/RECORD финального
  wheel в этой итерации не проверялись, поскольку wheel не создавался.
- Генератор --check, полное покрытие 1196 ключей и офлайн-импорт констант.
- Настоящий Paper 26.2 build 133 с независимым console observer: root и современные
  чтения, состояния лестницы/бревна, неверное свойство, отрицательные координаты,
  512 позиций за 8 страниц и барьер чтения после buffered setBlocks.
- Далёкий ранее незагруженный чанк сначала прочитан с генерацией, затем изменён
  без игрока: 0,454 с. Наблюдатель повторно загрузил освобождённый чанк и подтвердил
  сохранённый cobblestone до собственной подготовки позиции.
- Два отдельных Python-процесса одновременно заполнили разные слои одного
  чанка по 2048 блоков: примерно 1,13 и 1,33 с, без путаницы сессий.
- Стройка 65 536 блоков: 12,78 с. Второй клиент получил REGION_BUSY на пересечении
  и завершил независимую запись, пока первая стройка продолжалась.
- 100 отдельных setBlock+flush: медиана пяти повторов после прогрева 0,152 с
  (примерно 0,299 / 0,248 / 0,152 / 0,100 / 0,100 с). Это loopback-стенд и загруженные
  чанки, не обещание скорости любой генерации/сети.
- Остановка при ожидающей записи завершила клиента ошибкой связи без зависания;
  остановка Paper заняла около 0,689 с. Рабочие потоки и собственные процессы
  завершены, исходники/тестовые артефакты совпали с зафиксированными хешами.

В первом Paper-прогоне требовалось исправить тестовый oracle: он ожидал,
что далёкий чанк останется загруженным после корректного освобождения удержания.
Подготовка наблюдателя теперь проверяет исходный блок при независимой повторной
загрузке. После этой правки компактный прогон целиком прошёл; ошибка production
из-за этого не исправлялась и ложный успешный прогон не заявлялся.

Границы
--------

Заполнение ограничено 1 000 000 позициями, чтение — 262 144. Большое чтение не является
атомарным снимком при чужих изменениях. Физика, игроки и другие плагины могут
менять результат; резерв блокирует только конфликтующие мутации нашего API.
Отмена/ошибка не откатывает построенное. Состояния не означают автоматическую
достройку многоблочной конструкции или произвольное редактирование NBT.
