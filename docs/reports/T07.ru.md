Приёмка T07
===========

Дата: 20 октября 2026 года. Статус: выполнено.

Публичная цепочка Minecraft.create → setBlock → None → close работает через
установленный Python-пакет и настоящий Paper. Сохранены позиционные ip/port,
camelCase, числовой ID блока и block.COBBLESTONE. Оба пути setBlock используют
одну реализацию. Полная обязательная приёмка observer/gate остаётся T08–T10.

Реализация
----------

- minebridge.minecraft.Minecraft.create имеет согласованную сигнатуру
  (ip="localhost", port=4711, *, token=None, world=None, timeout=5.0, coordinates=None).
  Она ожидает connect_and_handshake и возвращает готовый фасад. При сбое сборки
  фасада новое соединение закрывается. from minebridge import Minecraft экспортирует
  тот же класс; канонический импорт из minebridge.minecraft сохранён.
- Read-only mc.blocks содержит один Blocks. Корневой mc.setBlock напрямую
  делегирует ему; таблица legacy, normalize_block, normalize_position и TCP
  не дублируются. Параметры обоих методов — x,y,z,block,data=0.
- В blocks.set отправляются нормализованные целые координаты, канонический ключ,
  пустые states и имя мира из hello. Для обмена установлен mutation=True.
  После проверенного applied=true возвращается None. Локальная ошибка не
  отправляет RPC и не расходует ID; доменные/транспортные ошибки сохраняют
  существующую классификацию code/outcome. Повторов и reconnect нет.
- close вызывает существующий неблокирующий относительно RPC-lock транспортный
  close, не отправляет RPC и безопасен при повторении. Repr не содержит token.
- Добавлен [examples/set_block.py](../../examples/set_block.py) с try/finally,
  числовым 4 и block.COBBLESTONE. В нём нужно задать координаты загруженного чанка
  своего стенда; токен берётся из MINEBRIDGE_TOKEN.
- Присутствуют статические типы, py.typed и документация методов. Импорт не
  открывает соединений. Публичные session metadata, context manager, новые kwargs,
  setBlocks/getPlayerEntityId/getBlock, игроки/SELF и селекторы не добавлялись.

Транспорт, codec, протокол 1.0, fixture и Java production-код не изменялись.
Повторная clean-сборка JAR совпала побитово с архивным T06. Архитектурные
решения не пересматривались; уточнения фасада записаны в
[контракте](../contracts/V0_1_CONTRACT.ru.md).

Контролируемые TCP peers проверяют ожидание hello и ACK, все формы BlockInput,
floor отрицательных дробей, выбор мира, локальные ошибки без расхода ID,
строгие keyword-only параметры, failed hello, доменную ошибку с последующим
успешным вызовом, чужой ID/EOF/ложный ACK, timeout и поздний ответ без повторов,
close при ожидающем RPC и два независимых клиента. Unknown outcome после
возможной отправки мутации не превращается в обещание отмены. Эти peers не
служат доказательством изменения Minecraft-мира — для него выполнен Paper smoke.

Настоящий Paper
----------------

tools/smoke_t07.py переиспользует ранее принятый EULA и отдельную консольную
fixture T06. tools/check_t07_client.py запускается с -I из установленного wheel.
Рабочие операции вызывают только публичные create/setBlock/close; private
_transport.context читается исключительно для корреляции теста.

1. Одновременно живут два отдельных CPython-процесса с разными PID и sessionId.
   A передаёт явный token, B использует MINEBRIDGE_TOKEN. Секрет поступает через
   окружение тестовых процессов, не argv/stdout. Контексты миров совпали с
   независимым снимком Paper API.
2. Оба setBlock проверены с 4, block.COBBLESTONE/AIR/STONE, современным ключом
   oak_planks и BlockSpec. Каждый успешный None сопоставлен с независимым
   консольным чтением BlockData. Отрицательная дробь -16383.75 записала x=-16384.
3. Проверены пять локальных/серверных отказов: bool-координата, неизвестный
   legacy ID, ненулевой data у современного ключа, предмет вместо блока и высота
   maxYExclusive. Контрольный блок сохранился; оба соединения остались рабочими.
4. Два процесса получили команды до ожидания любого ответа; перекрывающиеся
   публичные вызовы завершились независимо, итоговые блоки совпали с ожиданием.
5. После Paper stop два живых Python-объекта получили ConnectionError/
   CONNECTION_LOST/not-applied без reconnect. Их идемпотентный close завершился.
6. Restart повторно занял тот же порт: новый create и запись COBBLESTONE прошли.
   Занятый порт, пустой token конфигурации, отсутствующий defaultWorld и неверный
   YAML дали ожидаемые диагностические отказы.

В facade — 9 успешных записей/27 trace-событий, в restart — 1/3. Сравнивались
sequence, присвоенные в точках setter/публикации ACK, а не время stdout/TCP.
Токен отсутствовал в выводе сервера и Python-клиентов; неожиданных серверных
ERROR/SEVERE/FATAL нет. Тестовые процессы/listener завершились, fixture JAR убран.
Это smoke T07; полный V/D/N/F набор, world/position trace и управляемый gate
не заявляются выполненными до T08–T10.
