I04 — предметы, эффекты и создание сущностей
==========================================

на Paper 26.2 build 133 / Java 25. Установочная поставка JAR/wheel остаётся

Результат
---------

```python
from minebridge import Minecraft, items, effects, entity, selector
from minebridge.models import ItemStack

mc = Minecraft.create("localhost", 4711, player="CurrentNick")
try:
    reward = mc.players.giveItem(selector.SELF,
                                ItemStack(items.IRON_SWORD, name="Меч строителя"))
    buff = mc.effects.add(selector.ALL_PLAYERS, effects.SPEED, duration=30, level=2)
    cow = mc.spawnEntity(10, 80, 10, entity.COW)
    # Это настоящая молния с обычными игровыми последствиями.
    lightning = mc.spawnEntity(15, 80, 10, entity.LIGHTNING_BOLT)
finally:
    mc.close()
```

Доступны `players.giveItem`, `effects.add`, root `spawnEntity` и
`entities.spawn(type,x,y,z,...)`. Эти методы ждут результата в обоих writeMode
и являются барьером предшествующих buffered-записей. Создание, выдача и эффект
не повторяются автоматически при обрыве с неизвестным результатом.

InventoryResult отражает requested/given/leftovers/dropped по каждому UUID;
количество сохраняется. Полный инвентарь возвращает остатки, а явный
overflow="drop" выбрасывает их. Имя/lore передаются буквальным текстом.
Количество — 1..2304 на получателя, сервер использует настоящие размеры стеков.
Эффекты принимают игровые секунды с округлением вверх до тиков и level=1..256;
level=1 соответствует amplifier=0. Один TargetResolver обслуживает игроков
и живые сущности, сохраняя однократное разрешение и проверку всего набора целей.

Сущность создаётся с дробными координатами и возвращает UUID, runtime ID и key.
Живой тип возвращает LivingEntityRef. Чанк автоматически загружается/генерируется;
задания разделяют ChunkService с блоками и телепортацией, сохраняют FIFO,
heartbeat и освобождение удержаний. Длинная выдача/эффекты выполняются частями
с отдельным общим бюджетом gameplay jobs 2 мс за тик. Большой ожидаемый ответ
отклоняется до мутаций, если он не поместится в 64 КиБ.

Каталоги и специальные типы
--------------------------

Из закреплённого Paper экспортированы 1537 предметов, 40 эффектов и 158 реальных
типов сущностей. UNKNOWN отсутствует; AIR есть в предметном реестре, но не может
быть выдан. Все константы статические, типизированы различными ItemKey/EffectKey/
EntityTypeKey и доступны без подключения. Генератор --check прошёл.

Матрица: 150 обычных типов, 7 специальных, 1 неподдержанный PLAYER.
Все 150 обычных типов независимо созданы публичным World.spawnEntity в
одноразовом экспортирующем стенде: фактический тип совпал, validAtReturn=true.
Это проверка создания, а не обещание времени жизни или поведения AI.

Специальные адаптеры: ITEM с item, FALLING_BLOCK с block, PAINTING/ITEM_FRAME/
GLOW_ITEM_FRAME с face и опорой, FISHING_BOBBER с онлайн-владельцем, настоящая
LIGHTNING_BOLT. Все семь проверены через production API на итоговом Paper-стенде.
PLAYER требует настоящего входа клиента и получает UnsupportedEntityTypeError.
Недостающие/неприменимые параметры не игнорируются и не заменяют сущность свиньёй.

Условия стенда и границы результата
---------------------------------

Предварительные прогоны не объявлены приёмкой. В стенде исправлены две
предпосылки: UUID-поиск видит только загруженные сущности, а загруженный BORDER-
чанк ещё не обязательно симулирует сущности. Для рамок observer удерживает
собственную стену; для молнии выбирается обычная активная область рядом с
игроком, и готовность проверяется через публичные isTicking/ticksLived.
Гипотеза неверного класса damage-события опровергнута bytecode закреплённого
Paper. Причина различия повторных перемещений headless-игрока отдельно не
установлена и не выдаётся за дефект плагина или Minecraft-клиента.

Отдельная диагностическая сессия подтвердила урон, но получила внутреннюю
ошибку Paper POI при ранней остановке на фоне генерации; она не считается
успешной приёмкой. Итоговый полный прогон выше сохранил строгую проверку
остановки и прошёл без ошибок. Production и игровой сетевой клиент при этой
доводке стенда не изменялись; поведение не подменялось визуальной молнией.

Автозагрузка покрывает создание сущности; постоянный force-load или бессрочная
симуляция не включены. Дальнейшие AI, физика и молния подчиняются обычным условиям
мира. Произвольные NBT/компоненты/зачарования, новый тип сущности на клиенте,
события Python и scoreboard в I04 не добавлялись. Предварительные замечания
не заменяют итоговую проверку; подтверждённые ограничения отражены в контракте.

доводка документации и одна согласованная установочная пара JAR/wheel.
