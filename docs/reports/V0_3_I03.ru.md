## Реализовано

Каталог содержит 14 типов: CHAT_MESSAGE; BLOCK_INTERACT (alias BLOCK_HIT),
BLOCK_BREAK/BLOCK_PLACE; ENTITY_ATTACK/ENTITY_DAMAGE, PLAYER_DAMAGE;
PLAYER_ENTER_LAVA, PLAYER_JOIN/QUIT/DEATH/RESPAWN; PROJECTILE_SHOT/HIT.
PLAYER_DAMAGE — проекция того же факта урона: общий eventId/sequence и данные,
отдельные подписки и курсоры, без второго record в журнале.

Добавлены immutable typed модели, EventPosition/Region, каталог damageCause
из 33 native значений API133, короткие poll-методы и серверные фильтры игроков,
области и блоков. Состояния блока сохраняются в снимке; blocks-фильтр сравнивает
key. ALL_PLAYERS динамический, SELF закреплён за UUID; players=None включает
неигровых акторов. Новый тип проверяется по capability до отправки запроса;
совместимость формы чата I02 сохранена.

Новые native listeners используют MONITOR на game thread. Попытки/контакты
сохраняют статус отмены; отменённые результативные действия пропускаются.
Python не отменяет native event синхронно. ProjectileLaunch даёт один SHOT
на UUID; bow-контекст добавляет сведения, не создавая второй факт.
Контакт с лавой отслеживается отдельно от damage и выдаётся на переходе.

## Приёмка на Paper

Отдельный локальный offline сервер с ранее принятым EULA, два основных
игровых TCP-клиента и два независимых source-Python OS-процесса. Третий игровой
клиент используется для join/quit. Test-only observer независимо наблюдает
native события и фактическое состояние. Синтетические Bukkit events и вызовы
production capture API для имитации не используются.

1. Два Python PID/sessionId, реальные игровые соединения, capabilities всех типов.
2. Native break/place: снимки до ломания/замены; обработчик выполняет sync RPC
   и выдаёт предмет. Python setBlock не создаёт player break/place.
3. Пересечение Region/blocks/player-фильтров, отменённые break/place не входят
   в историю; обычная история остаётся без live-фильтров.
4. Реальные левый/правый клики, обе руки, отменённые попытки, общий alias-курсор.
5. Атака без выведенного из неё урона; настоящий damage и PLAYER_DAMAGE имеют
   общий eventId/sequence; отменённый damage исключён.
6. Bow, snowball, trident и crossbow: native item use/release, launch и block hit.
   Multishot даёт ровно три разных UUID, без duplicate SHOT. Bow/hand/force
   подтверждены там, где native API предоставляет эти сведения.
7. Контакт с сущностью и отменённый HIT сохраняют статус; отменённый launch
   не становится успешным SHOT.
8. Раздатчик имеет shooter=None/sourceBlock; players=None видит его,
   default ALL_PLAYERS исключает.
9. Новый игрок включается в ALL_PLAYERS; quit-снимок доступен после выхода;
   реальная смерть и клиентский respawn дают reason/location.
10. Лава: creative, survival, fire resistance, повторный контакт, отсутствие
    повторов внутри, новая подписка, teleport из лавы в лаву.
11. Растекающаяся лава охватывает неподвижного игрока; настоящий respawn
    с test-listener размещением в лаве приводит к подтверждённому isInLava.
12. Два процесса независимо читают типы/проекцию; native chat и projectile
    history не потребляют друг друга, clearAll не очищает чужое чтение.
13. Game-thread native oracle, clean close, отсутствие оставшихся Python-потоков.

Первичные fixture-прогоны честно сохранили allPassed=false. Проверки потребовали
реального player_loaded пакета 26.2, корректного getter прошедшего времени
использования предмета и явного native respawn-location override тестового
Java listener. Обычный force=true stored spawn не обещает размещение в лаве:
vanilla может выбрать безопасную точку. Финальный сценарий не выдаёт это
за способность Python менять/отменять respawn event.
