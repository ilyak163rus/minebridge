I01 — простое подключение и быстрый поток записей
================================================

Дата: 22 октября 2026 года. Итерация I01 выполнена; полный объём v0.2 ещё
не реализован. [План](../IMPLEMENTATION_PLAN_V0_2.ru.md),
[контракт](../contracts/V0_2_CONTRACT.ru.md), [запуск](../QUICKSTART.ru.md).

Что изменилось
--------------

- `Minecraft.create(ip, port)` подключается без обязательного токена.
  `authEnabled` по умолчанию false; явное включение сохраняет проверку токена.
- Основной мир автоматически определяется по `minecraft:overworld`.
  Старое поле defaultWorld принимается, игнорируется и отмечается сообщением
  при запуске. Имя папки не определяет мир подключения.
- `writeMode="buffered"` — режим по умолчанию; несколько запросов находятся
  в работе одновременно. Подтверждения по-прежнему отправляются после setter.
  `writeMode="sync"` сохраняет ожидание каждого вызова.
- `flush()` ждёт завершения предшествующих записей, обычный `close()` выполняет
  ожидание и освобождает соединение даже при ошибке. Повторный close безопасен.
- Серверные ошибки содержат тип, метод, request_id и outcome. При нескольких
  ошибках барьера первая несёт tuple `failures`. Ошибка может обнаружиться
  при следующей записи, flush или close; она не превращается в успешную запись.
- Один фоновый получатель ACK, окно до 128 запросов с учётом меньших удалённых
  лимитов, ограниченные очереди сервера 512/512. Игровой бюджет — 2 мс,
  до 128 коротких операций на сессию / 512 суммарно за тик.
- Активный wire-протокол 2.0. Смешивать старый клиент v0.1 с новым плагином
  не следует; архивные JAR/wheel и corpus v1 не перезаписаны.

Замеры на настоящем Paper
-------------------------

Среда: закреплённый Paper 26.2 build 133, JDK25, Python3.14.7, loopback TCP.
Четыре заранее загруженных/удерживаемых чанка, инертные материалы, 100 и 1000
последовательных setBlock. Координаты раскладывались сеткой шириной 32 блока;
это не замер генерации чанков и не проверка удалённой сети класса.

| Нагрузка | Время до подтверждённого завершения |
|---|---|
| Buffered, 100 блоков, пять повторов после прогрева | примерно 0,251 / 0,250 / 0,250 / 0,199 / 0,151 с |
| Медиана buffered100 | 0,2498 с; цель ≤0,5 с достигнута |
| Sync100 на том же сервере | 4,9997 с |
| Buffered1000, больше окна запросов | 1,0015 с |
| Два отдельных процесса, по 128 блоков одновременно | примерно по 0,1402 с |

Время включает flush, не только постановку команд. По медиане buffered100
примерно в 20 раз быстрее sync100 на этом стенде. Первый прогревочный пакет
занял около 0,600 с; он не включён в пять повторов. Универсальная гарантия
0,25 с для любого компьютера или первого холодного вызова не заявляется.
Проверка тик-счётчика наблюдателя дала приблизительно 20,62 тика/с по короткому
интервалу; это оценка tick-count/wall-clock, не точная серверная TPS-телеметрия.

Проверки
---------

- 396 Java cases, без ошибок/пропусков; активен общий корпус v2.
- По 126 Python-тестов на установленных wheel в отдельных Python3.11/3.14 venv.
- Реальный Paper: два свежих мира и три запуска, первый без авторизации,
  второй с другим именем мира и идентичным конфигом плагина, затем auth-on.
- Миры `i01-lesson-1` и `i01-lesson-2` получили разные UUID. В обоих случаях
  соединение выбрало minecraft:overworld без корректировки defaultWorld.
- Auth-off принимает обычное подключение без токена/переменной окружения;
  auth-on отвергает отсутствие/неверный токен и принимает правильный.
- Два отдельных Python-процесса одновременно держат разные сессии. Независимый
  console observer подтверждает реальные блоки после публичных ACK.
- InvalidBlockError и ChunkNotLoadedError обнаруживаются как через flush,
  так и через close; код, ID, метод и исход сохранены. Нет оставшихся потоков
  приёма у завершившихся клиентов; тестовые Paper-процессы штатно остановлены.
- Проба компиляции подтвердила публичные сигнатуры Paper133, нужные будущим
  итерациям: lookup мира по Key, async chunks/tickets, селекторы и EntityType,
  обычный spawn и молния. Это не реализация и не runtime-проверка этих функций.
