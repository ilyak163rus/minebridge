# Разработка Minebridge

Актуальные команды сборки и тестов — в [CONTRIBUTING](../CONTRIBUTING.md).
Для разработки нужны Python 3.11+ и JDK 25. Gradle запускается через wrapper;
первый запуск загружает закреплённые зависимости. Сборка библиотеки и Java-тесты
не требуют Minecraft-сервера.

## Структура проекта

| Каталог | Назначение |
|---|---|
| `python/src/minebridge` | Публичный Python API, транспорт, модели и типизированные каталоги |
| `python/tests` | Тесты установленного Python-пакета и проверки IDE |
| `plugin/src/main` | Paper-плагин, JSON-RPC, очереди и операции сервера |
| `plugin/src/test` | Java-тесты |
| `protocol` | Wire-формат, схемы и общий корпус примеров |
| `catalogs`, `compat` | Исходные каталоги и таблицы совместимости старых ID |
| `integration` | Отдельный тестовый observer и стенд настоящего Paper |
| `tools` | Генерация каталогов, сборка и проверки выпусков |

## Что проверять при изменениях

Для Python собирайте wheel, устанавливайте его в выбранное окружение и
запускайте `unittest` с `-I` вне исходников. Это обнаруживает отсутствующие
ресурсы и ошибки упаковки, которые маскируются импортом из `python/src`.

Для плагина запускайте `test shadowJar` через Gradle wrapper. Итоговый JAR
должен содержать зависимости плагина и не включать Paper, observer или тесты.
В CI используются Python 3.11/3.14 и JDK 25.

Изменения протокола проверяйте на обеих сторонах по общему корпусу `protocol`.
Технические правила поведения описаны в [контрактах](contracts).
Контракты ранних версий — историческая граница соответствующего API;
пользовательский справочник находится в [документации](README.md).

Изменения игровых операций дополнительно проверяйте на отдельном тестовом
Paper. Минимум — фактическое изменение мира после подтверждения, ошибки без
разрыва рабочего соединения и две независимые одновременные сессии.
[Интеграционный стенд](../integration/README.md) описывает ручную проверку и
ограничения автоматизированных runners.

## Каталоги и совместимость

Редактировать сгенерированные константы вручную не следует. Исходные данные,
происхождение и команды генерации описаны в [catalogs](../catalogs/README.md) и
[compat](../compat/README.md). После изменения источника регенерируйте каталог
и проверьте, что его состав соответствует выбранной версии сервера.

Совместимость `mcpi` ограничена проверенной таблицей старых ID/data и
сохранёнными методами. Новые блоки следует читать как `BlockSpec`; отсутствие
старого ID не означает отсутствие поддержки современного блока.

## Выпуск

Номера в `python/pyproject.toml`, `python/src/minebridge/__init__.py` и
`plugin/build.gradle.kts` должны совпадать. Плагин и библиотека распространяются
вместе; версия протокола меняется отдельно от версии продукта.

Порядок сборки, GitHub Release и необязательной публикации в PyPI — в
[инструкции для владельца проекта](PUBLISHING.ru.md). Локальные серверы,
окружения, журналы, результаты тестовых запусков и `dist/` не хранятся в Git.
